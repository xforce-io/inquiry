# Inquiry L2 v0.5.0 设计复核

日期：2026-11-02。目标版本：[L2 v0.5.0](../1-minimal-research-loop.md)。本记录是设计作者的缺陷复核与跨仓契约核对，不是独立代码审查、产品验收或人工架构批准；状态仍为 Draft。

## 发现与处置

| 发现 | 处置 | 结果 |
|---|---|---|
| 应用定义了框架推进/存储/执行关联，造成双份事实源 | 通用 Schema、模型、第二业务及机制迁入 TaskLoop Issue #2；本仓只保留业务资源 | 已修订，通用协议仅认 TaskLoop |
| 应用用共享表/内部 Run 获得展示信息，依赖过深 | D1–D5 只用五操作和公开 HostBindings；框架快照补输入与阶段定位 | 已修订，应用无私有表/调度/提交协议依赖 |
| 研究 ID 与执行 ID 双标识引入关联补偿 | 一期一研究一 ExecutionId，原始输入与已接受产物构建投影 | 已修订，删除第二状态库与 pending 关联恢复 |
| 证据和判断只有宽泛字符串，报告无法明确追溯分析依据 | analysis 增加 evidence；support/counter 解析本次证据；report 只引已接受证据 | 已修订，悬空证据/错版本/错位置/未分析引用拒绝 |
| 获取事实重复定义内部执行 ID | 领域 payload 只含获取语义，执行归属由框架受信信封提供 | 已修订，业务 Schema 拒绝 run_id |
| 旧模型绿色容易被当作应用已实现 | 框架模型留 TaskLoop，Inquiry 新建独立领域见证；真实接入明确 not_run | 已修订，不跨证据范围宣称通过 |

## 按用户关注点检查

| 关注点 | 设计结论与依据 |
|---|---|
| 依赖简洁 | 一个 Rust crate；start/get/signal/cancel/read_artifact；不增加执行服务、内部 DB 或重复状态表，见 L2 §8–9 |
| 架构合理 | Web 负责交互，薄宿主转换公开请求，业务包/工具/gate 负责研究；框架负责执行保证，见 §6–7 |
| 高内聚低耦合 | 研究状态和语义同仓；框架格式只消费不复制；两仓定义以公开输入/产物/错误衔接，见 §7–9 |
| 封装复杂、接口简单 | 无执行代数/Worker/内部提交协议；展示数据由公开快照直接提供，错误由框架返回而非应用修表 |
| 扩展有界 | 以后新增研究阶段/工具/评价规则走业务定义和公开注册；独立业务编辑/存储、上传/发布不预建 |
