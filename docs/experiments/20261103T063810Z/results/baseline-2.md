# 决策报告：以Playwright为主，有限引入浏览器Agent

**研究截止：2026-11-03T06:38:10Z。**本次未实时联网核验，无法确认截止时点的最新产品能力、报价、数据政策和榜单。下述公开结果仅代表所列来源，不是本团队实测。

## 一、结论先行

未来8周建议采用**“自有产品确定性回归＋第三方操作分级混合＋高风险操作人工兜底”**，不要整体替换为浏览器Agent。

- **自有产品回归：**以Playwright脚本、明确断言和GitHub Actions为发布保障。Agent可辅助编写、诊断和提出修复，但不得在运行时修改断言、绕过失败后宣布通过。
- **第三方后台：**优先使用获授权的官方API；没有合适API时，稳定流程用脚本，变化较多的低风险流程试验混合方案。低频且人工处理很快的任务，可以不自动化。
- **支付、删除、权限变更等高风险操作：**8周内不开放无人值守执行；无法隔离权限或核验结果的任务保留人工。

**支持依据：**现有TypeScript和Actions降低接入成本；自有产品能控制测试数据、页面契约与结果验证；第三方变化则可能使固定脚本维护不经济。  
**反对依据：**脚本仍需维护；混合方案增加模型、策略和审计成本，5人团队可能得不偿失。Agent若在低风险任务中显著降低总人工工时，也不应因技术偏好而排除。

因此，这不是永久选型，而是**有预算上限、有对照、有退出条件的试点**。目前不能承诺具体成功率提升或投资回报。

## 二、先区分工具层与决策层

Playwright是浏览器控制与测试工具；Agent负责理解目标、选择动作及处理变化。**Agent完全可以通过Playwright操作浏览器，两者不是互斥产品类别。**

| 方案 | 自有产品回归 | 第三方后台操作 |
|---|---|---|
| 确定性脚本 | 默认选择；路径和断言可审查、结果可复现 | 适合稳定、高频、有明确结果凭证的流程 |
| Agent主导 | 适合探索、诊断和生成候选测试，不宜独立承担发布门禁 | 适合低频、只读、允许人工复核的非标准任务 |
| 混合方案 | 脚本执行与判定，Agent辅助维护 | 固定登录、数据校验和提交边界，Agent仅处理受限页面理解或路径变化 |

混合方案的价值不在“失败后让模型随便再试”，而在于**变化部分交给模型，正确性和权限边界留在确定性代码与服务端权限中**。如果模型可以任意点击、改验收规则、直接提交，它仍是宽权限Agent，而非受控混合。

先盘点现有约30条流程的归属、频率、损失等级、登录方式和结果凭证，不假定它们都应每次发布运行。

## 三、可靠性：机制、公开证据与不能外推的部分

### 1. Playwright能减少哪些失败

Playwright执行动作前会检查相应的可操作性条件；官方建议使用面向用户的定位器、显式测试契约和可重试断言，而不是固定等待时间。[1][2]这些机制有助于降低元素尚未就绪、动画和异步渲染带来的竞态。

但它们**不保证业务正确**：点击成功不等于订单保存成功，出现提示也不等于后台事务完成。可靠回归仍依赖隔离的数据、稳定账号以及对业务终态的断言。

典型失败包括脆弱选择器、共享数据冲突、认证失效、网络抖动、第三方依赖异常和断言过弱。重试可能掩盖问题；Playwright也明确区分首跑通过、重试后通过和失败。[3]团队应分别记录，不能把重试后的绿色当作无波动。

### 2. Agent证据说明什么

WebArena提供可复现的网站环境与功能性任务评测，适合研究多步骤网页操作，但不是本团队生产环境。[4]OpenAI在2025年CUA发布材料中报告WebArena成功率58.1%、WebVoyager成功率87%。[5]

这些是**厂商报告的特定评测结果**，不是本次独立复测，也不能推出“本团队成功率为87%”。不同测试的任务分布、页面环境、模型配置、尝试预算和判定方式不同；更不能据此断言它优于本团队尚未测量的脚本方案。它们没有回答本团队真实账号权限、验证码、发布变化、数据泄露及长期维护问题。

Agent的额外失败模式包括：误解任务、选错对象、长步骤中偏离目标、错误判断完成、超时，以及将页面上的恶意指令当成操作要求。间接提示注入是公开识别的风险；外部网页必须被当作不可信数据，而非授权来源。[6]

尤其对回归测试，**“聪明地绕开故障”可能恰好漏报产品缺陷**。因此，模型不能同时拥有执行路径、验收标准和最终裁决权。

### 3. 本团队应如何测量

使用同一任务定义、起始条件和独立终态校验器比较方案：

- 同时报告首尝试自主成功率、含人工最终完成率、重试率、计划审批次数和非计划接管率。
- 登录失败、验证码、限流和超时必须计入，不剔除难例来提高分数。
- 回归中的真实产品缺陷与自动化误报分开统计；用历史缺陷或受控故障检查漏报。
- 模型自述“已完成”不算成功；优先核验记录ID、业务状态或审计记录。无法可靠核验时转人工。

按流程、站点、风险和版本分组，避免大量容易任务掩盖关键流程失败。即使100次零失败，在独立同分布假设下，95%单侧失败率上界仍约3%；重复同一环境通常相关，证据更弱。试点阈值不是生产可靠性的统计保证。

## 四、成本、人工与权限边界

### 成本应覆盖失败和维护

建议核算：

> 总成本＝运行与平台费用＋模型费用＋建设维护工时＋审批及接管工时。  
> 每个核验成功任务成本＝上述全部成本÷核验成功任务数。

安全事故损失另列风险，不用难以验证的概率折算后将其忽略。Agent费用需按实际供应商计费单位、上下文增长、截图和重试记录；当前单价未知，不提供虚构报价。

**量级示例，均为假设：**若30条流程每次发布各跑一次，8周16次发布就是480次流程执行；若每次独占runner两分钟，则约960 runner分钟，尚未包括启动、PR检查、夜间运行、多浏览器和重试。这不能代表实际账单，却能帮助区分“流程数”和“计费工作量”。

建议试点最多投入**96工程小时**：轮值负责人每周8小时，另预留团队评审与维护4小时。运行、模型及平台现金支出先封顶**人民币2000元**。若假设全成本为300元/工程小时，人力预算为28800元；这只是预算情景，需替换为团队真实成本，维护不得重复计入。

第三方任务偶发时，建设成本可能无法摊薄；维护脚本或Agent都比人工处理更贵，应允许“不做”。

### 权限与数据必须由系统限制

1. **环境隔离：**回归使用测试账号和合成数据；第三方使用专用最小权限账号。生产会话不得进入执行不可信PR代码的任务。
2. **凭据隔离：**密码、令牌和会话由执行环境保管，不交给模型。Playwright官方明确提示认证状态文件可能包含可用于冒用身份的敏感信息，不应提交仓库。[7]
3. **数据边界：**截图、DOM、下载和trace可能包含客户数据。送入模型前做最小化与脱敏；先核实处理地域、保存期限、训练用途、子处理商及删除机制。未知政策不能默认安全。
4. **执行边界：**限定域名、账号、动作、时间、步数及费用；不开放通用终端、任意网络请求和任意脚本能力。只列域名白名单不足以阻止站内误删。
5. **人工接管：**遇到验证码、异常权限、对象歧义或未知页面即停止，不自动规避。接管包应包含目标、已执行动作、当前状态和未完成事项，不能仅给一张报错截图。

### 不可逆操作单独控制

优先采用“读取—拟定变更—展示差异—独立批准—确定性提交—核验”。批准必须绑定具体对象、金额或字段；状态变化后重新批准，网页文字不能代替批准。

Agent只提出结构化方案，提交由受限执行器完成。**若无法隔离浏览器里的任意写入能力，就不能仅靠提示词声称提交已受控**；应改用真正只读账号或人工执行。

提交后超时属于“结果未知”，先查业务记录，不盲目重试。支持时使用幂等键，否则依靠业务去重及人工确认；有些动作只能补偿，不能真正回滚。

## 五、最小架构与选择条件

不建设多Agent平台或通用“自愈”框架。沿用仓库与Actions，增加五个薄层：

> 版本化任务定义 → 调度与权限检查 → 脚本／受限Agent → 独立结果验证 → 审计与人工接管

任务定义包含前置条件、允许动作、预算、终态和停止条件。固定或记录浏览器、模型、提示词及工具版本；不能锁定的服务升级需重新评估。失败留存经脱敏的trace，便于定位，而不是全量永久保存；Playwright提供执行轨迹查看能力。[8]

选择顺序如下：

- 有合适且获授权的官方API：优先API，浏览器只覆盖必要的界面路径。
- 自有产品或第三方稳定流程：优先脚本。
- 确有页面变化导致的维护负担，且低风险、可核验：试混合。
- 一次性、只读、人工易复核：可用Agent主导。
- 权限不可隔离、结果不可核验、操作不可恢复：人工。

若脚本达到同等可靠性且更便宜，就不保留Agent；若混合能减少维护且不放大权限，再有限扩大。

## 六、8周试点、验收与退出

以下均为**建议门槛，不是已测事实或对外SLA**。

| 周次 | 工作与交付 |
|---|---|
| 第1—2周 | 盘点30条流程；定义最高优先级P0；记录现有人工与脚本耗时、失败和接管；选8—10条自有回归、2—3类低风险第三方任务；确认数据政策与权限。 |
| 第3—4周 | 将选定回归接入Actions；先观察再启用稳定门禁；第三方在可复位环境比较脚本、Agent和混合，保持任务与终态校验一致。 |
| 第5—6周 | 按风险补覆盖；注入页面变化、会话过期、网络失败、错误业务状态和恶意页面指令；第三方先只读，再试经批准的可逆写入。 |
| 第7—8周 | 冻结候选配置，跨日期验证；汇总成功率、缺陷检出、接管、延迟和全成本；逐流程决定保留、降级或停止。 |

不为凑样本重复执行生产写入，也不要求8周强行自动化全部30条。

**验收指标：**

- **自有回归：**健康基线至少100次流程执行，所选关键流程各不少于10次；首跑通过率≥98%，历史缺陷及受控故障样本全部被检出。发布前所有P0必须有有效自动化结果或人工签字；重试、跳过不能掩盖失败。回归批次目标P95≤10分钟，排队时间另记。
- **第三方：**至少30组可比低风险任务，跨日期并覆盖不同状态。只读任务自主成功率目标≥90%；Agent须在可靠性或总人工工时上优于脚本，并且按相同8周工作量摊销后的每成功任务成本不高于人工基线。需要批准的写任务单独统计，不能冒充自主成功。
- **安全：**未经批准写入、越权、向未批准目的地传送敏感数据均为零；受控安全测试全部通过。但“未观察到事故”不等于风险为零。
- **负担：**末两周维护与接管合计≤4工程小时/周；不突破试点预算。

**退出条件：**发现越权、泄露或未批准写入，立即停用相关执行器、撤销凭据并人工核对影响；缺乏可靠终态验证或合格数据条款，不接生产。连续两周维护超标、成本超限或Agent没有净收益，退回脚本／人工。回归脚本不稳定则暂撤阻塞资格，恢复人工发布清单，不能通过削弱断言“修绿”。

最终仍需补测：30条流程实际分布、人工基线、认证摩擦、UI变化频率、维护时间、模型账单和数据合同。**样本不足或尚未经历真实变化，就保留辅助资格，不扩大无人值守权限。**
