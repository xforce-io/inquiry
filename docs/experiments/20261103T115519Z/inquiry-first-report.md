# 决策：先试 FTS5，第二周以中文效果决定是否换轨

**建议以 SQLite 保存权威来源版本，优先试 FTS5；Tantivy 是需要更多中文与排序控制时的备选，Meilisearch 是开箱语言能力确实节省开发投入时的备选。** 这不是速度排行榜：三者在本团队数据上的相关性、资源、恢复时间和成本均未测。少一个服务有利于压缩交付范围，但不能据此排除 Meilisearch。

两名开发者合计每周2人日，8周只有**16人日**。应只交付一种检索实现、固定版本阅读与引用、备份恢复及可观察的失败状态，不建设三套生产系统。第二周若 FTS5 中文短词适配不能在预算内达标，就停止追加投入；备选也不达标则缩小规模，不牺牲引用正确性换取“上线”。

## 一、三种方案的边界

| 方案 | 默认或已有公开依据 | 必须自行建设、主要风险 | 采用条件 |
|---|---|---|---|
| SQLite FTS5 | 默认 unicode61；可选 trigram；可与版本元数据放在同库事务 | 中文预分词、查询一致性与原文定位；外部内容表可能与索引失步 | 中文验收通过，且容量、恢复满足要求 |
| Tantivy | Rust 检索库，不是现成服务 | 中文适配器、查询接口、提交与读者刷新；主键不自动唯一，跨库一致性需维护 | 可测收益抵偿额外接入和维护工作 |
| Meilisearch | 独立服务，官方有多语言处理与按书写系统分流的说明 | 服务生命周期、异步任务核验、鉴权、备份迁移；接收请求不等于索引成功 | 同一语料上省下的适配人时或相关性收益足够，8GB资源检查通过 |

**FTS5。** unicode61 是默认分词器，但按字符类别处理不等于中文词典分词。[1] trigram 可辅助子串检索，不过全文查询少于3个 Unicode 字符不匹配，不能单独覆盖常见双字词。[2] 建议先验证统一版本的中文预分词字段，必要时增加 trigram 辅助字段；索引与查询须使用同一分词配置。短语、标点、大小写和原文偏移应分开测试，不能把分词后高亮直接当引用位置。

最小实现先用普通内容 FTS 表；不要为了尚未测出的空间收益过早采用 external-content。后者要求应用保持内容表与索引一致，须事务化增删改并验证既有数据回填。[3] 典型失败不是数据库完全不能查，而是旧词仍命中、新词漏检或内容与结果不符。

**Tantivy。** 它不是开箱服务，嵌入 Rust 仍需要建设业务接口。[4] tantivy-jieba 示例要求额外依赖和注册 tokenizer，属于接入能力而非默认中文能力；选定 crate 与适配器的兼容性、词典许可仍待核实。[5] 本次证据不足以完整确认默认分析器行为，不以“Rust 原生”推断中文可用。

应用应按稳定主键删除再添加完成更新，并处理提交及读者刷新。官方示例明确不会强制一个 ID 仅对应一个文档，遗漏删除或错误重放可产生重复结果。[6] 架构文档说明提交时原子更新 meta.json；这不等于与 SQLite 元数据原子提交，也不是所有断电、磁盘故障的耐久性保证。[7]

**Meilisearch。** 厂商说明覆盖空格分隔语言和中文等语言，分词文档说明先按 script 拆分字段。[8][9] 这是降低中文接入工作的理由，不证明领域词、简繁、代码混排的相关性优胜，更不代表默认跨语言语义检索。其任务异步处理；2024年问题讨论显示曾出现把批处理日志当作任务成功的误判。[10] 应保存 task ID、轮询终态，再核对命中；删除完成前以应用墓碑过滤旧结果。具体版本的替换/部分更新、字段清除和重复请求语义尚未完整核验，须列入试验，不能凭通用 API 印象实现。

三者比较必须锁定版本、字段与分词配置。Tantivy 0.25 变更记录列有对0.24 union性能回归的修复，历史性能不能混算。[11] 此处不声称0.25是研究截止时最新版。

## 二、最小架构：版本库才是事实源

建议主路径为：**Rust 本地应用 → 权威版本库与不可变正文 → 可重建索引 → 命中核验 → 固定版本阅读**。以下是应用设计，不是三种引擎附赠的引用保证。

每次获取建立 source_id、version_id、原始/最终 URL、抓取时间、原始及规范正文哈希、解析器版本、段落序号和字符偏移。引用固定为“version_id＋规范正文哈希＋段落/偏移＋短引文”；URL、内部 DocId、搜索高亮均不能独立承担长期定位。

正文文件先完整写入并校验，再提交数据库中的可见记录。中断产生的孤立文件可回收，未就绪正文不得发布。FTS5 路径把版本记录与索引变更放在同库事务；Tantivy 或 Meilisearch 路径则在权威库写待索引事件，幂等重放，记录索引代次与处理水位，核验完成后标为可检索。仅实现选中路径，不先做通用插件平台。

读取结果时核对版本、哈希、删除状态；不一致就隐藏并告警，不能猜引用。来源更新生成新版本，不覆盖旧引文目标。逻辑删除和依法彻底清除要分开：前者不应意外破坏历史引用；后者须覆盖缓存与备份策略，旧引用可能只能显示“已删除”。这项保留政策必须事先确认。

## 三、持久化、恢复与迁移

FTS5 与元数据同库减少跨存储协调，但耐久性仍取决于配置。SQLite WAL 的 FULL 会在每次事务提交同步日志，不能把 NORMAL 的掉电行为与之混同，也不应靠放松耐久性获得好看的速度。[12] 活跃数据库不要仅复制主文件；官方备份 API 提供一致性副本路径。[13]

Tantivy 保留已提交索引，并以权威版本库作为可重建依据；尚未证明任意跨版本索引兼容。Meilisearch 文档区分日常保护的 snapshot 与版本迁移的 dump，升级步骤要求先备份；不能将某个升级选项当作任意版本免迁移保证。[14][15] 搜索引擎备份也不能替代应用原网页备份。

共同流程是：锁定版本，备份权威库和正文，在独立目录恢复或重建，核对版本计数、哈希与引用，再切换索引代次；保留旧程序和索引至验收。杀进程试验仅验证相应中断路径，不能称为真实掉电证明。恢复时间和已提交数据是否完整必须实测。

## 四、许可、成本与数据边界

SQLite 官方声明 Public Domain。[16] Meilisearch 已保存页面区分 MIT 社区版与 BUSL 企业版，不能把所有功能都算作免费社区能力。[17][18] 本次未从已接受证据确认 Tantivy 的明确许可证文本；锁定 tag 后核验 LICENSE 是发布门槛，Rust 绑定、分词器与词典亦须分别核验，不以印象补齐。

自托管不等于天然无泄漏。建议服务仅监听 loopback，验证未授权读写被拒绝，限制数据目录权限，检查遥测、日志与抓取凭据。嵌入式减少监听面，但网页仍是不可信文本：转义展示、参数化查询、限制查询复杂度。试点不接外部模型。引擎许可证不赋予抓取、保留或再分发网页的权利。

成本统一按8周、相同语料和任务量记录：
- 人时＝建设＋中文适配＋标注验收＋部署升级备份＋故障接管。按每人日8小时的**预算假设**，总上限128小时。
- 现金＝增量机器、存储、备份与许可费用；同一机器不重复计购置费。已有报价和人时单价均未知，不能承诺零成本或节省比例。
- 磁盘＝原文＋规范正文＋元数据＋索引＋备份＋迁移新旧双份＋临时空间。10万份不是字节量，应先抽样长度分布再测放大。

建议总工作集目标不超过6GB，为系统留余量；这是预算而非引擎官方限制。新增硬件、付费功能或备份服务须另确认报价。服务可能省开发人时，嵌入式也可能增加适配负担，必须比较完整投入。

## 五、8周安排与验收闸门

以下分工、样本和阈值均为**建议，试点前需确认**。A负责存储索引，B负责标注与交叉核验；不假设已有脚本或测试资产。

| 周次 | 合计人日 | 产出与停止条件 |
|---|---:|---|
| 1–2 | 4 | A用2日做共同导入和三个极薄探针；B用2日抽2000份分层网页、标注60查询。只选一个主方案、至多一个备选；中文关不过就换轨 |
| 3–4 | 4 | A用3日完成版本库、引用和增删改；B用1日核对。错版引用未解决不扩量 |
| 5–6 | 4 | A用2日做备份恢复和资源采样；B用2日扩至10万份并做故障核验。不通过则不承诺全量上线 |
| 7–8 | 4 | A修复1日、B盲测1日，留2日用于接管、文档或一次小范围备选切换；超预算则缩范围 |

探针或标注超时就声明小规模 MVP，不挪用可靠性工时；备选若需超过预留2日，不强行本轮切换。拿不到10万真实资料，容量即未验收。

**检索质量。** 60查询分中文、英文、混合各20，覆盖单/双字、简繁、专名、代码标点、短语、无结果。B对匿名合并 Top10 标0/1/2相关，A抽核分歧。Hit@10＝Top10含相关结果的有答案查询数/有答案查询数，建议≥90%，关键中文短词不得系统性漏检。nDCG@10按每查询DCG/已标池IDCG计算再平均，零IDCG单列；候选改善≥0.05且资源合格才考虑额外复杂度，不称统计显著。无答案误报率单列，分母为无答案查询数；池内标注不能证明全库召回率。

**正确性。** 新增、更新、删除、重复重放各25次；另抽100个跨版本/重建引用。版本、哈希、段落、引文全部一致条数/抽查条数应为100%。一次错版引用或已删除内容泄漏即阻止上线。健康操作正确完成与故障正确拦截分开计数，不能把正确报错算失败，也不能把全绿当正确。

**故障与资源。** 写入、提交、索引完成前后杀进程，以及磁盘满、队列失败、快照损坏，各场景至少3次；记录正确拦截告警数/植入故障数、错误阻止健康操作数/健康操作数，分别报告首轮、一次重放后和人工接管结果。建议索引滞后≤60秒，暖查询p95≤300毫秒、冷启动首查≤2秒；10万导入后测100次冷/暖查询，报告尾延迟、峰值内存与磁盘。重复运行不是独立样本。

建议查询2秒超时、导入批次30分钟未完即诊断、单方案全量导入最多2小时；正常重启≤5分钟，备份恢复或重建≤2小时，已确认提交的来源版本不得丢失。内存持续超过6GB、磁盘不足以留备份和重建空间、版本核验失败即停写索引保留正文。

第8周正确性仍不过，退出自动检索，提供版本目录、元数据筛选和人工打开固定原文，明确显示“索引不可用/待重建”，保留日志和待处理项。不是假设已有旧搜索系统可回退。

## 六、结论的适用范围

公开 BEIR 比较使用各自英文分析配置及特定数据集，不能预测这里的中文混合效果。[19] 所有采集晚于研究截止时间2026-11-03T11:55:19Z：可辨日期与版本的历史证据仍有参考价值，但滚动文档不能证明截止时最新版或配置。因此这是**有停止条件的选型建议，不是截止时版本认证或生产保证**。

支持 FTS5 的核心是缩小一致性与部署范围；反对它的核心是中文短词与适配成本。若 Meilisearch 实测明显节省适配工作，应接受服务；若 Tantivy 的中文与排序控制带来足够收益，应接受更多工程责任。最终决定只在同一语料、权限、耐久性和完整成本口径下作出。

## 研究限制

- 所有材料采集晚于研究截止时间；滚动页面、仓库主分支和示例不能认证截止时最新版或历史默认配置。
- 无团队相关性、延迟、内存、磁盘、恢复或完整成本实测；人时、样本及阈值都是建议，不构成统计保证或已确认承诺。
- Tantivy许可证、分词依赖兼容及许可、默认分析器、所有持久性异常边界尚未充分核验；Meilisearch具体版本更新端点、默认安全和遥测配置及收费条款也未完整核实。
- 部分候选获取失败或截断，尤其未取得的IndexWriter源码限制了Tantivy异常边界结论；历史issue不能代表当前普遍缺陷。
- 尚未确认现有实现、测试资产或维护分工；语料字节量、保留删除政策、索引滞后与恢复目标及现金预算需试点前确认。
- 小样本、池化标注与开发者交叉复核存在偏差；2000份探针不证明10万份容量，杀进程恢复不证明断电耐久性。
